# AGENTS.md — working on Minecraft Server Census

Guidance for AI coding agents (and humans) touching this repository. Read `README.md` first for what the project *is*;
this file is about how to change it safely.

## What this is, in one paragraph

A single Node.js 24 + TypeScript process (`src/server/`) that pings every tracked Minecraft Java Edition server every 10 minutes,
stores the results in SQLite (`node:sqlite`, no native modules), de-duplicates hostnames that are the same server, and
serves a **public, read-only** JSON API plus a React dashboard (`src/web/`, built with Vite and served from memory by the same
process). There is no authentication and no write endpoint on purpose; writes happen only through the CLI (`src/server/cli.ts`).

## Layout

```
src/server/index.ts       boot: open DB, import seeds, start HTTP + scheduler
src/server/db.ts          schema (CREATE TABLE IF NOT EXISTS on every start), all SQL that writes, hourly rollup (server_hours)
src/server/rollup-worker.ts  one-time server_hours backfill on its own thread (started by scheduler.ts)
src/server/dedup.ts       pure de-duplication rules (union-find); MergeReason is the vocabulary used by the UI
src/server/sweep.ts, scheduler.ts, probe.ts, geo.ts, blocklist.ts   collector jobs
src/server/discovery/     seed-file import (runs at boot) + the manual `discover` list-site scraper (read-only, writes a txt for review)
src/server/protocol/      Server List Ping (modern + legacy), DNS/SRV resolution, protocol-version table
src/server/api/queries.ts every read query behind the API; Scope = all | one country
src/server/api/routes.ts  route table (GET only), run by the reader thread (reader.ts, reader-client.ts) on a read-only connection
src/server/api/cache.ts   per-sweep response cache (stale-while-revalidate one version); invalidated by scheduler.ts
src/server/api/http.ts    HTTP server: /api/health + favicons on the main thread, everything else via cache -> reader; ETag/gzip
src/server/api/static.ts  serves dist/web from memory (gzip, immutable /assets/*, SPA fallback for / and /server/*)
src/server/cli.ts         operator commands (add, remove, country, discover, suspects, regroup, groups, prune, blocklist, ping, probe, sweep, stats, compact, thin)
src/web/index.html        Vite entry (root: src/web); src/web/public/ holds the favicon and icon sprite
src/web/lib/api.ts        TanStack Query hooks, one per endpoint
src/web/lib/types.ts      hand-written mirror of the API JSON shapes — update it whenever queries.ts changes a shape
src/web/lib/motd-parse.ts pure MOTD parser (no React, no path aliases) so the root test runner can import it
src/web/components/ui/    generated by the shadcn CLI (Base UI variants); prefer `npx shadcn add` over hand edits
src/web/components/{layout,filters,dashboard,server,common}/   app components
src/web/pages/            DashboardPage, ServerPage, NotFoundPage (React Router, createBrowserRouter)
test/                     node:test suites, run against the TypeScript sources with tsx
data/seeds/*.txt          curated host lists, re-imported at every start (idempotent); data/db/ is the live SQLite (git-ignored)
tsconfig.json             backend (src/server, NodeNext -> dist/server); tsconfig.web.json: frontend (src/web, bundler, @/ alias)
vite.config.ts            root = src/web, outDir = dist/web, /api proxied to :8080 in dev
```

## Commands

```bash
npm install            # single package: backend + frontend deps in one node_modules
npm run dev            # both: tsx watch on the backend (:8080) + Vite with HMR (:5173, proxies /api) — open the Vite URL
npm run dev:server     # backend only (serves dist/web if it exists)
npm run dev:web        # Vite only
npm run typecheck      # tsc -p tsconfig.json + tsc -p tsconfig.web.json
npm test               # node --import tsx --test test/*.test.ts
npm run build          # dist/server (tsc) + dist/web (vite)
npm start              # production: node dist/server/index.js
```

In dev, open the URL Vite prints (5173, or the next free port if something else holds it) — :8080 only serves the last
`npm run build:web` output. The process loads `dist/web` into memory at startup and **reloads it automatically** when the
directory changes, so `npm run build:web` is enough to refresh a running server (dev or prod).

## Conventions and gotchas

* **Backend imports keep the `.js` suffix** (NodeNext). The frontend has its own tsconfig (`tsconfig.web.json`: DOM lib,
  bundler resolution, `@/` alias); never add `src/web` to the root `tsconfig.json` `include`.
* **Never interpolate user input into SQL.** Country codes are validated by `parseScope` (`/^[A-Z]{2}$/`) and always bound
  with `?` via `scopeFilter()` / `sweepSource()`. Column names for sorting come from the `SORTS` allow-list.
* **The API is read-only.** Do not add POST/PUT/DELETE routes, auth, or exports; anything that mutates state goes in
  `src/server/cli.ts`. Non-GET requests to `/api/*` get a 405.
* **Schema changes are additive.** `db.ts` applies `CREATE TABLE IF NOT EXISTS` on every start; adding a table or index
  needs no version bump (see `sweep_countries` + `backfillSweepCountries()` for the pattern). Adding or dropping a column
  of an existing table goes in `migrate()` (`ALTER TABLE`, guarded by `PRAGMA table_info`), so the live database is never
  deleted; anything that cannot be expressed that way would need a `SCHEMA_VERSION` bump — avoid.
* **De-duplication semantics**: sweep totals sum the MAX player count per group; `*_raw` columns keep the naive sum.
  Per-country totals (`sweep_countries`) attribute a group to every country any member belongs to. `servers.group_rep/
  group_reason` reflect only the latest sweep and are cleared for offline servers; `pings.group_rep/group_reason` are history.
  After changing rules in `dedup.ts`, run `npm run regroup` and keep `test/dedup.test.ts` green. There are no manual
  merge overrides.
* **Country** = `COALESCE(servers.country_override, servers.tld_country, servers.country)` (`COUNTRY_SQL` in `db.ts`,
  re-exported as `COUNTRY_EXPR`; `serverCountry()` for loaded rows): operator override, then ccTLD, then GeoIP. Bump
  `COUNTRY_RULE` when the expression changes so every sweep is re-aggregated on the next start. Backfilled history uses
  each server's *current* country. In the API `country` is always the effective one; the server page adds `geo_country`.
* **Time**: the API buckets in UTC (`/api/profile` returns UTC weekday × hour); the client shifts to the viewer's timezone
  in `src/web/lib/profile.ts`. `bucketSeconds()` decides raw / hourly / 6-hourly points and is shared by the timeseries and
  the server history. **node:sqlite binds JS numbers as REAL**: arithmetic on a bound value needs `CAST(? AS INTEGER)`
  (`started_at / ?` is float division and silently does not bucket).
* **Pings are the bulk of the database (~0.7 M rows/day) and of the write load.** `pings` has one index,
  `(sweep_id, server_id)`: read one server's history with `sweep_id IN (SELECT id FROM sweeps WHERE started_at >= ?) AND
  server_id = ?` (a seek per sweep), never `WHERE server_id = ?` alone (full scan). Anything longer than
  `RAW_HISTORY_HOURS` (72 h) reads `server_hours` (per server and UTC hour of the sweep's start, answered pings only) plus
  the raw tail after `rollupThrough()` (`hourlyRows()` in queries.ts). Do not add indexes on `pings`: each one is a random
  page write per ping. New ping rows reference their snapshot (`snapshot_id`); `status_hash`/`version_name` are only set on
  rows written before that. A server's snapshot sightings accumulate in `servers.snapshot_pending` and are flushed every
  `SNAPSHOT_FLUSH_PINGS`; readers add them back (see `serverPage`).
* **Never run a plain `VACUUM` on the app's connection**: `temp_store = MEMORY` makes it copy the whole database into RAM
  (the Fly machine has 1 GB). `compact` + `compactIfRequested()` use `VACUUM INTO` at startup instead.
* **API reads never run on the main thread.** node:sqlite is synchronous; a slow query there stalls the sweep (in-flight
  pings time out) and the Fly health check. Add routes to `routes.ts`; mark a route `cacheable: false` only when it carries
  live state (the overview). Cached replies are recomputed at most once per sweep/probe run, whatever the number of tabs.
* **MOTD rendering**: never `dangerouslySetInnerHTML`. `motd-parse.ts` produces styled runs; `Motd.tsx` renders spans on a
  dark slab. Legacy payloads are `{"legacy": "§1\0<proto>\0<version>\0<motd>\0<online>\0<max>"}` — split on `\0`.
* **Charts** use shadcn `ChartContainer` over Recharts. Give every container an explicit height (`h-[320px]` or the
  `style={{ height }}` prop) or Recharts renders 0px. Colours come from `--chart-1..5` in `src/web/styles/globals.css`
  (a validated colour-blind-safe palette with separate dark-mode steps); text never wears the series colour.
* **Base UI popups** are portalled; `#root { isolation: isolate }` keeps them above the sticky header. The country combobox
  pins `initialFocus` to its search input.
* **Static serving**: only `/` and `/server/*` fall back to `index.html` (hostnames contain dots, so "no extension" is not a
  usable heuristic). Add new client routes to `SPA_PREFIXES` in `static.ts` **and** to the router in `src/web/App.tsx`.
* **Site name** lives in `src/web/lib/site.ts`, `src/web/index.html` `<title>`, `src/server/api/static.ts` (not-built page) and
  `README.md`.
* Do not commit `dist` or `data/db`. There is one `package.json` / `package-lock.json` at the root; do not add a nested one.
* The Dockerfile copies seeds with `--chmod=644` because host files can be `0600`; keep that when adding copied files.
  `node:24-slim` is used for both stages; there are no native modules so Alpine also works.

## Testing expectations

* `npm run typecheck && npm test` must pass before finishing a change.
* New query logic gets a test that opens a temp `Db` (see `test/sweep-countries.test.ts`: insert servers/pings with plain
  SQL, call `finishSweep`/`groupSweep`, assert rows).
* UI changes: `npm run build` must succeed; check the page at desktop and ~390px width and in both themes.
* Avoid running commands that mutate `data/db/census.db` (e.g. `npm run add`, `npm run country`, `npm run prune`) unless
  that is the task — it is the live dataset. Tests must use temp databases.
